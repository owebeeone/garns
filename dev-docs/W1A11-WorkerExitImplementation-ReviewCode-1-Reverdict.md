## 1. Findings

### [P3-8] A registry that has begun closing can still join; the following `close_outcome` mutates local state before refusing

**Location:** `src/garns/backends/contracts/lifetime_reference.py:247-252` (`open_lifetime` consults no local resource state) and `generation_reference.py:108-136` (`join_runtime` has no local-state input); `lifetime_reference.py:1535-1550` (`close_outcome` transitions resources to `LOCAL_CLOSED` at 1539–1540 and retires admissions at 1542–1543, then calls `witness_local_close` at 1550, which refuses at `generation_reference.py:165-167` when the drain was never witnessed because `start_close` ran before the join).
**Violated invariant:** Design §9 — a registry closing before activation reaches only `UNJOINED → LEFT` and "later open/join on that registry refuses"; overlay §4 / A16 validate-then-commit ("a refusal preserves owner, state and charges"); RemPlan IR9 "`close_outcome` validates before mutating".
**Reproduction (N1):** construct a registry, `add_resource(runtime)`, `start_close(runtime)` (runtime `local_draining`, membership `None` so no drain is witnessed); `open_lifetime()` → OK, membership `joined`; `close_outcome(runtime)` → `ContractRefusal(local_resource_draining, "local close requires the witnessed drain fence")` with the runtime already `local_closed` and admissions `RETIRED`; membership remains `joined`, participants 1. A second `start_close(runtime)` (now JOINED, so the drain is witnessed) followed by `close_outcome` reaches CLOSED and `left`.
**Impact:** bounded and recoverable; requires the nonsensical ordering open-after-start-close. Not a regression — Revision1 left a permanent ghost JOINED member on a CLOSED runtime for the same sequence — but the corrected path still refuses after a partial mutation and briefly holds a JOINED member on a LOCAL_CLOSED runtime, which a later attempt would freeze into its required set until the caller repeats the close.
**Classification:** bounded source repair; no design change.
**Required correction:** `open_lifetime` refuses once the runtime resource has left `LOCAL_OPEN` (or once `start_close(runtime)` has run); `close_outcome` checks `drain_witnessed`/membership preconditions before transitioning any resource.
**Closure test:** `start_close(runtime)` on an unjoined registry → `open_lifetime` refuses (`ACTIVATION_REQUIRED`), `close_outcome` → CLOSED via `close_unjoined`; alternatively, if a join is somehow present, `close_outcome` refuses with resources, admissions and membership unchanged.
